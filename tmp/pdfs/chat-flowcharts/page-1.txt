Memory scope and shared services
Semantic: organizationId + sessionId. A new session excludes old Semantic context; it does not require physical
deletion. Procedural and Episodic: organizationId. threadId: identifies checkpoint/resume state. employeeId /
userId: request metadata; business data remains organization-scoped.
Every scenario uses the /chat API, graph state, PostgreSQL memory search and the checkpointer. recordEpisode summarizes
and saves the outcome. These internal storage operations are separate from business tools.
Design status
These charts describe the agreed target design. The inspected branch currently has get_customers, create_customer and
server_time. It still needs session scope, the merged prompt/intent call, batch Semantic review, an active/status customer filter,
and an orders tool. The current eight-planning-turn cap can also limit large paginated fetches.
Memory examples below are illustrative, not confirmed stored records. None of these three prompts requests a business write; the
write-review, Semantic-save and resume branches remain visible but inactive.
